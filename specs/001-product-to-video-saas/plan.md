# Implementation Plan: ProductToVideo.ai — URL-to-Video SaaS Platform

**Branch**: `001-product-to-video-saas` | **Date**: 2026-02-02 | **Spec**: `specs/001-product-to-video-saas/spec.md`
**Input**: Feature specification + technical requirements from `docs/planPrompt.md`

## Summary

Build a full-stack SaaS application that converts e-commerce product URLs into promotional videos. Users paste a URL, the system extracts product data via headless scraping, generates an AI video script (Claude Haiku), lets users customize a Remotion-based video template, and renders downloadable MP4 files. The platform supports English/Arabic (RTL), dark/light themes, Stripe subscription billing with render quotas, and bulk video generation.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20+
**Framework**: Next.js 15 with App Router (full-stack)
**Primary Dependencies**: next-intl, @supabase/ssr, remotion v4, @remotion/player, @remotion/renderer, @anthropic-ai/sdk, puppeteer-core, @sparticuz/chromium-min, stripe, shadcn/ui, Tailwind CSS v4, motion (Framer Motion), next-themes, resend, franc, nuqs
**Storage**: Supabase PostgreSQL + Supabase Storage (3 buckets: rendered-videos, product-images, avatars)
**Testing**: Vitest for unit tests, Playwright for E2E
**Target Platform**: Web (responsive: desktop, tablet, mobile). Self-hosted Node.js server for video rendering.
**Performance Goals**: URL-to-MP4 in <60 seconds (single 9:16). Live preview updates <2 seconds. 90% extraction success rate across top 10 platforms.
**Constraints**: Vercel serverless 250MB limit excludes @remotion/renderer — rendering must be self-hosted. Remotion bundler cannot run inside API routes (webpack conflict). Stripe legacy usage records deprecated — must use Billing Meters API.
**Scale/Scope**: B2C SaaS, initial hundreds of users. 7 user stories, 65 functional requirements, ~40 source files, 10 DB tables.

**Structure Decision**: Single full-stack Next.js project (not monorepo). Remotion compositions live in `src/remotion/` and are shared between the client Player and the server renderer via pre-bundling. API routes handle all backend logic. Supabase provides auth, DB, and storage as managed services.

## Complexity Tracking

No constitution violations to justify.

| Decision | Rationale |
|----------|-----------|
| Self-hosted rendering (not Lambda) | Simpler MVP architecture; avoids AWS setup. Migrate to Lambda when scaling. |
| App-side quota tracking (not Stripe-only) | Real-time enforcement requires local DB state. Stripe Meters handle billing only. |
| Composed middleware (not separate) | Single middleware.ts handles both i18n and auth. Avoids request duplication. |
| Pre-bundled Remotion (not runtime bundling) | @remotion/bundler includes Webpack, cannot bundle-within-Webpack in API routes. |
